99=head1 NAME
100
101feature - Perl pragma to enable new features
102
103=head1 SYNOPSIS
104
105 use feature qw(fc say);
106
107 # Without the "use feature" above, this code would not be able to find
108 # the built-ins "say" or "fc":
109 say "The case-folded version of $x is: " . fc $x;
110
111
112 # set features to match the :5.36 bundle, which may turn off or on
113 # multiple features (see "FEATURE BUNDLES" below)
114 use feature ':5.36';
115
116
117 # implicitly loads :5.36 feature bundle
118 use v5.36;
119
120=head1 DESCRIPTION
121
122It is usually impossible to add new syntax to Perl without breaking
123some existing programs. This pragma provides a way to minimize that
124risk. New syntactic constructs, or new semantic meanings to older
125constructs, can be enabled by C<use feature 'foo'>, and will be parsed
126only when the appropriate feature pragma is in scope. (Nevertheless, the
127C<CORE::> prefix provides access to all Perl keywords, regardless of this
128pragma.)
129
130=head2 Lexical effect
131
132Like other pragmas (C<use strict>, for example), features have a lexical
133effect. C<use feature qw(foo)> will only make the feature "foo" available
134from that point to the end of the enclosing block.
135
136 {
137 use feature 'say';
138 say "say is available here";
139 }
140 print "But not here.\n";
141
142=head2 C<no feature>
143
144Features can also be turned off by using C<no feature "foo">. This too
145has lexical effect.
146
147 use feature 'say';
148 say "say is available here";
149 {
150 no feature 'say';
151 print "But not here.\n";
152 }
153 say "Yet it is here.";
154
155C<no feature> with no features specified will reset to the default group. To
156disable I<all> features (an unusual request!) use C<no feature ':all'>.
157
158=head1 AVAILABLE FEATURES
159
160Read L</"FEATURE BUNDLES"> for the feature cheat sheet summary.
161
162=head2 The 'say' feature
163
164C<use feature 'say'> tells the compiler to enable the Raku-inspired
165C<say> function.
166
167See L<perlfunc/say> for details.
168
169This feature is available starting with Perl 5.10.
170
171=head2 The 'state' feature
172
173C<use feature 'state'> tells the compiler to enable C<state>
174variables.
175
176See L<perlsub/"Persistent Private Variables"> for details.
177
178This feature is available starting with Perl 5.10.
179
180=head2 The 'smartmatch' feature
181
182C<use feature 'smartmatch'> tells the compiler to enable the
183smartmatch operator C<~~>. It is enabled by default, but can be
184turned off to disallow the C<~~> operator.
185
186This feature is disabled by default in the 5.42 feature bundle
187onwards:
188
189 $x ~~ $y; # fine
190 use v5.42;
191 $x ~~ $y; # error
192
193This has no effect on the implicit smartmatches done by C<when>.
194
195See L<perlop/"Smartmatch Operator"> for details.
196
197=head2 The 'switch' feature
198
199C<use feature 'switch'> tells the compiler to enable the Raku
200given/when construct.
201
202See L<perlsyn/"Switch Statements"> for details.
203
204This feature is available starting with Perl 5.10. It is enabled by
205feature bundles 5.10 through 5.34, and disabled from the 5.36 feature
206bundle onwards.
207
208=head2 The 'unicode_strings' feature
209
210C<use feature 'unicode_strings'> tells the compiler to use Unicode rules
211in all string operations executed within its scope (unless they are also
212within the scope of either C<use locale> or C<use bytes>). The same applies
213to all regular expressions compiled within the scope, even if executed outside
214it. It does not change the internal representation of strings, but only how
215they are interpreted.
216
217C<no feature 'unicode_strings'> tells the compiler to use the traditional
218Perl rules wherein the native character set rules is used unless it is
219clear to Perl that Unicode is desired. This can lead to some surprises
220when the behavior suddenly changes. (See
221L<perlunicode/The "Unicode Bug"> for details.) For this reason, if you are
222potentially using Unicode in your program, the
223C<use feature 'unicode_strings'> subpragma is B<strongly> recommended.
224
225This feature is available starting with Perl 5.12; was almost fully
226implemented in Perl 5.14; and extended in Perl 5.16 to cover C<quotemeta>;
227was extended further in Perl 5.26 to cover L<the range
228operator|perlop/Range Operators>; and was extended again in Perl 5.28 to
229cover L<special-cased whitespace splitting|perlfunc/split>.
230
231=head2 The 'unicode_eval' and 'evalbytes' features
232
233Together, these two features are intended to replace the legacy string
234C<eval> function, which behaves problematically in some instances. They are
235available starting with Perl 5.16, and are enabled by default by a
236S<C<use 5.16>> or higher declaration.
237
238C<unicode_eval> changes the behavior of plain string C<eval> to work more
239consistently, especially in the Unicode world. Certain (mis)behaviors
240couldn't be changed without breaking some things that had come to rely on
241them, so the feature can be enabled and disabled. Details are at
242L<perlfunc/Under the "unicode_eval" feature>.
243
244C<evalbytes> is like string C<eval>, but it treats its argument as a byte
245string. Details are at L<perlfunc/evalbytes EXPR>. Without a
246S<C<use feature 'evalbytes'>> nor a S<C<use v5.16>> (or higher) declaration in
247the current scope, you can still access it by instead writing
248C<CORE::evalbytes>.
249
250=head2 The 'current_sub' feature
251
252This provides the C<__SUB__> token that returns a reference to the current
253subroutine or C<undef> outside of a subroutine.
254
255This feature is available starting with Perl 5.16.

257=head2 The 'array_base' feature
258
259This feature supported the legacy C<$[> variable. See L<perlvar/$[>.
260It was on by default but disabled under C<use v5.16> (see
261L</IMPLICIT LOADING>, below) and unavailable since perl 5.30.
262
263This feature is available under this name starting with Perl 5.16. In
264previous versions, it was simply on all the time, and this pragma knew
265nothing about it.

267=head2 The 'fc' feature
268
269C<use feature 'fc'> tells the compiler to enable the C<fc> function,
270which implements Unicode casefolding.
271
272See L<perlfunc/fc> for details.
273
274This feature is available from Perl 5.16 onwards.

276=head2 The 'lexical_subs' feature
277
278In Perl versions prior to 5.26, this feature enabled
279declaration of subroutines via C<my sub foo>, C<state sub foo>
280and C<our sub foo> syntax. See L<perlsub/Lexical Subroutines> for details.
281
282This feature is available from Perl 5.18 onwards. From Perl 5.18 to 5.24,
283it was classed as experimental, and Perl emitted a warning for its
284usage, except when explicitly disabled:
285
286 no warnings "experimental::lexical_subs";
287
288As of Perl 5.26, use of this feature no longer triggers a warning, though
289the C<experimental::lexical_subs> warning category still exists (for
290compatibility with code that disables it). In addition, this syntax is
291not only no longer experimental, but it is enabled for all Perl code,
292regardless of what feature declarations are in scope.
293
294=head2 The 'postderef' and 'postderef_qq' features
295
296The 'postderef_qq' feature extends the applicability of L<postfix
297dereference syntax|perlref/Postfix Dereference Syntax> so that
298postfix array dereference, postfix scalar dereference, and
299postfix array highest index access are available in double-quotish interpolations.
300For example, it makes the following two statements equivalent:
301
302 my $s = "[@{ $h->{a} }]";
303 my $s = "[$h->{a}->@*]";
304
305This feature is available from Perl 5.20 onwards. In Perl 5.20 and 5.22, it
306was classed as experimental, and Perl emitted a warning for its
307usage, except when explicitly disabled:
308
309 no warnings "experimental::postderef";
310
311As of Perl 5.24, use of this feature no longer triggers a warning, though
312the C<experimental::postderef> warning category still exists (for
313compatibility with code that disables it).
314
315The 'postderef' feature was used in Perl 5.20 and Perl 5.22 to enable
316postfix dereference syntax outside double-quotish interpolations. In those
317versions, using it triggered the C<experimental::postderef> warning in the
318same way as the 'postderef_qq' feature did. As of Perl 5.24, this syntax is
319not only no longer experimental, but it is enabled for all Perl code,
320regardless of what feature declarations are in scope.

322=head2 The 'signatures' feature
323
324This enables syntax for declaring subroutine arguments as lexical variables.
325For example, for this subroutine:
326
327 sub foo ($left, $right) {
328 return $left + $right;
329 }
330
331Calling C<foo(3, 7)> will assign C<3> into C<$left> and C<7> into C<$right>.
332
333See L<perlsub/Signatures> for details.
334
335This feature is available from Perl 5.20 onwards. From Perl 5.20 to 5.34,
336it was classed as experimental, and Perl emitted a warning for its usage,
337except when explicitly disabled:
338
339 no warnings "experimental::signatures";
340
341As of Perl 5.36, use of this feature no longer triggers a warning, though the
342C<experimental::signatures> warning category still exists (for compatibility
343with code that disables it). This feature is now considered stable, and is
344enabled automatically by C<use v5.36> (or higher).
345
346=head2 The 'refaliasing' feature
347
348B<WARNING>: This feature is still experimental and the implementation may
349change or be removed in future versions of Perl. For this reason, Perl will
350warn when you use the feature, unless you have explicitly disabled the warning:
351
352 no warnings "experimental::refaliasing";
353
354This enables aliasing via assignment to references:
355
356 \$a = \$b; # $a and $b now point to the same scalar
357 \@a = \@b; # to the same array
358 \%a = \%b;
359 \&a = \&b;
360 foreach \%hash (@array_of_hash_refs) {
361 ...
362 }
363
364See L<perlref/Assigning to References> for details.
365
366This feature is available from Perl 5.22 onwards.
367
368=head2 The 'bitwise' feature
369
370This makes the four standard bitwise operators (C<& | ^ ~>) treat their
371operands consistently as numbers, and introduces four new dotted operators
372(C<&. |. ^. ~.>) that treat their operands consistently as strings. The
373same applies to the assignment variants (C<&= |= ^= &.= |.= ^.=>).
374
375See L<perlop/Bitwise String Operators> for details.
376
377This feature is available from Perl 5.22 onwards. Starting in Perl 5.28,
378C<use v5.28> will enable the feature. Before 5.28, it was still
379experimental and would emit a warning in the "experimental::bitwise"
380category.
381
382=head2 The 'declared_refs' feature
383
384B<WARNING>: This feature is still experimental and the implementation may
385change or be removed in future versions of Perl. For this reason, Perl will
386warn when you use the feature, unless you have explicitly disabled the warning:
387
388 no warnings "experimental::declared_refs";
389
390This allows a reference to a variable to be declared with C<my>, C<state>,
391or C<our>, or localized with C<local>. It is intended mainly for use in
392conjunction with the "refaliasing" feature. See L<perlref/Declaring a
393Reference to a Variable> for examples.
394
395This feature is available from Perl 5.26 onwards.

397=head2 The 'isa' feature
398
399This allows the use of the C<isa> infix operator, which tests whether the
400scalar given by the left operand is an object of the class given by the
401right operand. See L<perlop/Class Instance Operator> for more details.
402
403This feature is available from Perl 5.32 onwards. From Perl 5.32 to 5.34,
404it was classed as experimental, and Perl emitted a warning for its usage,
405except when explicitly disabled:
406
407 no warnings "experimental::isa";
408
409As of Perl 5.36, use of this feature no longer triggers a warning (though the
410C<experimental::isa> warning category still exists for compatibility with
411code that disables it). This feature is now considered stable, and is enabled
412automatically by C<use v5.36> (or higher).

414=head2 The 'indirect' feature
415
416This feature allows the use of L<indirect object
417syntax|perlobj/Indirect Object Syntax> for method calls, e.g. C<new
418Foo 1, 2;>. It is enabled by default, but can be turned off to
419disallow indirect object syntax.
420
421This feature is available under this name from Perl 5.32 onwards. In
422previous versions, it was simply on all the time. To disallow (or
423warn on) indirect object syntax on older Perls, see the L<indirect>
424CPAN module. It is disabled from the 5.36 feature bundle onwards.
425
426=head2 The 'multidimensional' feature
427
428This feature enables multidimensional array emulation, a perl 4 (or
429earlier) feature that was used to emulate multidimensional arrays with
430hashes. This works by converting code like C<< $foo{$x, $y} >> into
431C<< $foo{join($;, $x, $y)} >>. It is enabled by default, but can be
432turned off to disable multidimensional array emulation.
433
434When this feature is disabled the syntax that is normally replaced
435will report a compilation error.
436
437This feature is available under this name from Perl 5.34 onwards. In
438previous versions, it was simply on all the time. It is disabled from
439the 5.36 feature bundle onwards.
440
441You can use the L<multidimensional> module on CPAN to disable
442multidimensional array emulation for older versions of Perl.
443
444=head2 The 'bareword_filehandles' feature
445
446This feature enables bareword filehandles for builtin functions
447operations, a generally discouraged practice. It is enabled by
448default, but can be turned off to disable bareword filehandles, except
449for the exceptions listed below.
450
451The perl built-in filehandles C<STDIN>, C<STDOUT>, C<STDERR>, C<DATA>,
452C<ARGV>, C<ARGVOUT> and the special C<_> are always enabled.
453
454This feature is available under this name from Perl 5.34 onwards. In
455previous versions it was simply on all the time. It is disabled from
456the 5.38 feature bundle onwards.
457
458You can use the L<bareword::filehandles> module on CPAN to disable
459bareword filehandles for older versions of perl.

461=head2 The 'try' feature
462
463B<WARNING>: This feature is still partly experimental, and the implementation
464may change or be removed in future versions of Perl.
465

467handling, where exceptions thrown from the body of the block introduced with
468C<try> are caught by executing the body of the C<catch> block.

482=head2 The 'defer' feature

496=head2 The 'extra_paired_delimiters' feature
497
498B<WARNING>: This feature is still experimental and the implementation may
499change or be removed in future versions of Perl. For this reason, Perl will

502 no warnings "experimental::extra_paired_delimiters";
503
504This feature enables the use of more paired string delimiters than the

510with a declaration such as C<use utf8>.

512This feature is available starting in Perl 5.36.
513
514For a full list of the available characters, see
515L<perlop/List of Extra Paired Delimiters>.

517=head2 The 'module_true' feature
518
519This feature removes the need to return a true value at the end of a module
520loaded with C<require> or C<use>. Any errors during compilation will cause
521failures, but reaching the end of the module when this feature is in effect
522will prevent C<perl> from throwing an exception that the module "did not return
523a true value".
524

526

534which implement the "new" object system, previously codenamed "Corinna".

679The C<:default> bundle represents the feature set that is enabled before
680any C<use feature> or C<no feature> declaration.
681
682Specifying sub-versions such as the C<0> in C<5.14.0> in feature bundles has
683no effect. Feature bundles are guaranteed to be the same for all sub-versions.
684
685 use feature ":5.14.0"; # same as ":5.14"
686 use feature ":5.14.1"; # same as ":5.14"
687
688You can also do:
689
690 use feature ":all";
691
692or
693
694 no feature ":all";
695
696but the first may enable features in a later version of Perl that
697change the meaning of your code, and the second may disable mechanisms
698that are part of Perl's current behavior that have been turned into
699features, just as C<indirect> and C<bareword_filehandles> were.
700
701=head1 IMPLICIT LOADING
702
703Instead of loading feature bundles by name, it is easier to let Perl do
704implicit loading of a feature bundle for you.
705
706There are two ways to load the C<feature> pragma implicitly:
707
708=over 4
709
710=item *
711
712By using the C<-E> switch on the Perl command-line instead of C<-e>.
713That will enable the feature bundle for that version of Perl in the
714main compilation unit (that is, the one-liner that follows C<-E>).
715
716=item *
717
718By explicitly requiring a minimum Perl version number for your program, with
719the C<use VERSION> construct. That is,
720
721 use v5.36.0;
722
723will do an implicit
724
725 no feature ':all';
726 use feature ':5.36';
727
728and so on. Note how the trailing sub-version
729is automatically stripped from the
730version.
731
732But to avoid portability warnings (see L<perlfunc/use>), you may prefer:
733
734 use 5.036;
735
736with the same effect.
737
738If the required version is older than Perl 5.10, the ":default" feature
739bundle is automatically loaded instead.
740
741Unlike C<use feature ":5.12">, saying C<use v5.12> (or any higher version)
742also does the equivalent of C<use strict>; see L<perlfunc/use> for details.
743
744=back

754 use feature ();

790=item feature_bundle()

803
804 use feature ();
