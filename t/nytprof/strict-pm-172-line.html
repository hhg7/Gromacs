86=head1 NAME
87
88strict - Perl pragma to restrict unsafe constructs
89
90=head1 SYNOPSIS
91
92 use strict;
93
94 use strict "vars";
95 use strict "refs";
96 use strict "subs";
97
98 use strict;
99 no strict "vars";
100
101=head1 DESCRIPTION
102
103The C<strict> pragma disables certain Perl expressions that could behave
104unexpectedly or are difficult to debug, turning them into errors. The
105effect of this pragma is limited to the current file or scope block.
106
107If no import list is supplied, all possible restrictions are assumed.
108(This is the safest mode to operate in, but is sometimes too strict for
109casual programming.) Currently, there are three possible things to be
110strict about: "subs", "vars", and "refs".
111
112=over 6
113
114=item C<strict refs>
115
116This generates a runtime error if you
117use symbolic references (see L<perlref>).
118
119 use strict 'refs';
120 $ref = \$foo;
121 print $$ref; # ok
122 $ref = "foo";
123 print $$ref; # runtime error; normally ok
124 $file = "STDOUT";
125 print $file "Hi!"; # error; note: no comma after $file
126
127There is one exception to this rule:
128
129 $bar = \&{'foo'};
130 &$bar;
131
132is allowed so that C<goto &$AUTOLOAD> would not break under stricture.
133
134
135=item C<strict vars>
136
137This generates a compile-time error if you access a variable that was
138neither explicitly declared (using any of C<my>, C<our>, C<state>, or C<use
139vars>) nor fully qualified. (Because this is to avoid variable suicide
140problems and subtle dynamic scoping issues, a merely C<local> variable isn't
141good enough.) See L<perlfunc/my>, L<perlfunc/our>, L<perlfunc/state>,
142L<perlfunc/local>, and L<vars>.
143
144 use strict 'vars';
145 $X::foo = 1; # ok, fully qualified
146 my $foo = 10; # ok, my() var
147 local $baz = 9; # blows up, $baz not declared before
148
149 package Cinna;
150 our $bar; # Declares $bar in current package
151 $bar = 'HgS'; # ok, global declared via pragma
152
153The local() generated a compile-time error because you just touched a global
154name without fully qualifying it.
155
156Because of their special use by sort(), the variables $a and $b are
157exempted from this check.
158
159=item C<strict subs>
160
161This disables the poetry optimization, generating a compile-time error if
162you try to use a bareword identifier that's not a subroutine, unless it
163is a simple identifier (no colons) and that it appears in curly braces,
164on the left hand side of the C<< => >> symbol, or has the unary minus
165operator applied to it.
166
167 use strict 'subs';
168 $SIG{PIPE} = Plumber; # blows up
169 $SIG{PIPE} = "Plumber"; # fine: quoted string is always ok
170 $SIG{PIPE} = \&Plumber; # preferred form
171
172=back
173
174See L<perlmodlib/Pragmatic Modules>.
175
176=head1 HISTORY
177
178C<strict 'subs'>, with Perl 5.6.1, erroneously permitted to use an unquoted
179compound identifier (e.g. C<Foo::Bar>) as a hash key (before C<< => >> or
180inside curlies), but without forcing it always to a literal string.
181
182Starting with Perl 5.8.1 strict is strict about its restrictions:
183if unknown restrictions are used, the strict pragma will abort with
184
185 Unknown 'strict' tag(s) '...'
186
187As of version 1.04 (Perl 5.10), strict verifies that it is used as
188"strict" to avoid the dreaded Strict trap on case insensitive file
189systems.
190
191Beginning with Perl 5.12, use of "use VERSION" (where VERSION >= 5.11.0) now
192lexically enables strictures just like "use strict" (in addition to the normal
193"use VERSION" effects and features.) In other words, "use v5.011" or higher
194now implies "use strict" automatically, as noted in
195L<perl5120delta/"Implicit strictures"> and L<C<use VERSION>|perlfunc/use VERSION>.
